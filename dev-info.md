
# Developer info / in case I forget


## Table stack

The searchable table on the main page is composed of three layers:

```
app/page.tsx
  └─ PpdDataTable           (PPD-specific wrapper; picks URL + columns)
       └─ GenericDataTable  (table-agnostic DataTables component)
            └─ POST /api/v1/<table>/dtajax
                 └─ dtajax2sql -> SQL -> better-sqlite3 -> ppd.db
```

- **`app/components/GenericDataTable/GenericDataTable.tsx`** knows nothing
  about PPD's tables. It wraps `datatables.net-react` in server-side
  processing mode and POSTs each DataTables request object to whatever
  `ajaxUrl` it's given. It's the piece intended to be reusable in other
  projects (and eventually extractable into a package alongside
  [dtajax2sql](https://www.npmjs.com/package/dtajax2sql)).

- **`app/components/PpdDataTable/PpdDataTable.tsx`** is the PPD-specific
  instantiation: given a `TableName`, it derives the endpoint URL, pulls
  the column definitions from `lib/column-definitions.ts`, and looks up
  per-table extras (enhanced-search modes, DataTables option overrides)
  in its `perTableConfig` object.

- **`lib/api/make-dtajax-handler.ts`** makes the endpoint handlers: it
  translates the request into SQL (via `dtajax2sql`), runs it read-only
  against `ppd.db`, and answers in the DataTables server-side protocol
  (`draw` / `recordsTotal` / `recordsFiltered` / `data`). The route
  files under `pages/api/v1/<table>/dtajax/` are two-liners that
  instantiate it.


## GenericDataTable

```tsx
import GenericDataTable from '@/app/components/GenericDataTable/GenericDataTable';

<GenericDataTable
  ajaxUrl="api/v1/sometable/dtajax"
  columns={ someColumnDefs }
/>
```

| Prop | Required | What it do |
| --- | --- | --- |
| `ajaxUrl` | yes | dtajax-style endpoint the table POSTs to |
| `columns` | yes | DataTables column definitions |
| `id` | no | id for the `<table>` element |
| `searchModes` | no | `{ value, label }[]`; renders a dropdown and sends the selection as `globalSearchMode` with every request. First entry is the initial selection. Omit it and no dropdown renders / no key is sent. |
| `searchModesLabel` | no | label text for the dropdown (default: "Global search option:") |
| `options` | no | DataTables config, merged (shallowly, per top-level key) over the component's defaults |

Defaults worth knowing about (see the component for the full set):
server-side processing, `pageLength: 10`, `scrollX`, `fixedHeader`,
`fixedColumns: { start: 5 }`, SearchBuilder on top, and colvis / copy /
csv / excel buttons whose exports use the `'export'` orthogonal type
(which is what makes the redaction in `lib/utils.ts` work). Any of these
can be overridden per-table via `options` - note that overriding a
top-level key like `layout` replaces that key wholesale.


### What's the deal with `globalSearchMode`?

When `searchModes` is present, the request body is the DataTables
request object plus a `globalSearchMode` key. The dtajax endpoint routes
any value other than `"classic"` through `dtajax2sql`'s
`toSQLThroughFtTable`, using the value as the name of an FTS5 table in
`ppd.db`. So a mode's `value` must match an FTS5 table name generated by
`mk-ppd-db/scripts/make-fttables-sql.ts` (driven by the `$metadata.ftTables`
annotations in `mk-ppd-db/json-schemas/main.schema.json`).


### How to add a table page

1. Pipeline: add `mk-ppd-db/01_make-each-table/<table>.R` and
   `mk-ppd-db/json-schemas/<table>.schema.json`, then `make && make install`
   in `mk-ppd-db/`. Everything else (types, column defs, db constants,
   the `TableName` union) is generated.
2. API: add `pages/api/v1/<table>/dtajax/index.ts` - a two-liner that
   default-exports `makeDtajaxHandler('<table>')`
   (from `lib/api/make-dtajax-handler.ts`).
3. UI: add a page that renders `GenericDataTable` (or extend
   `PpdDataTable`'s lookup) with that table's columns and URL.
4. Decorate columns (clipping, links, redaction, non-searchable fields)
   in `lib/column-definitions.ts`.


## Auto-generated files

Produced by the `mk-ppd-db` pipeline when `make install` copies them into the
app. Never edit by hand!

- `types/record-types.d.ts` - one record type per DB table + the
  `TableName` union
- `lib/proto-column-definitions.ts` - base DataTables column definitions
- `lib/db-constants.ts` - per-table row counts and primary-key bounds
